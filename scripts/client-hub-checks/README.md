# Проверка постов и сообщений без настоящих площадок

Настоящие Telegram, MAX и ВКонтакте в проверках не участвуют: пост, отправленный «для пробы», увидят подписчики. Вместо них — локальный имитатор площадок `provider-emulator.mjs`. Он слушает только `127.0.0.1`, принимает любой токен и ничего не отправляет наружу.

## Что проверяется само

`corepack pnpm --filter @an30/messaging test` (входит в `corepack pnpm test` и в CI) поднимает имитатор и ведёт через него настоящий клиент площадок (`packages/messaging/src/provider-emulator.test.ts`): правка поста меняет опубликованный, а не создаёт второй; пост с фото и замена фото; отказ Telegram добавить фото к текстовому посту и убрать его из поста с фото; отказ площадки; потерянный ответ («Нужна проверка»); повтор отправки ВКонтакте с тем же ключом не создаёт дубль.

`corepack pnpm --filter @an30/api client-hub:smoke` — сквозная проверка API и worker на «тестовых» подключениях (47 проверок, площадки не вызываются вовсе). Ей нужен запущенный стенд и `HUB_PREVIEW_PASSWORD_FILE`.

## Стенд с имитатором: посмотреть глазами

```bash
node scripts/client-hub-checks/provider-emulator.mjs            # http://127.0.0.1:4901, порт можно передать первым аргументом
# API и worker — с одной и той же переменной (в production она запрещена: сервис не запустится)
HUB_PROVIDER_EMULATOR_URL=http://127.0.0.1:4901 … node apps/api/dist/main.js
HUB_PROVIDER_EMULATOR_URL=http://127.0.0.1:4901 … node apps/worker/dist/main.js
```

Дальше — как на рабочем сайте: **Посты и мессенджеры → Площадки → Подключить площадку**, «Тестовый режим» снять, токен любой (для Telegram — вида `123456:любые-буквы`). ВКонтакте для постов нужны оба ключа: сообщества и администратора. Канал Telegram — `@имя` или `-100…`, стена ВК — `-номер сообщества`.

| Запрос к имитатору | Что делает |
| --- | --- |
| `GET /_emulator/state` | Что «опубликовано» на каждой площадке (текст, фото, число правок) и список принятых вызовов. Токены не хранятся |
| `POST /_emulator/fault` с телом `{"platform":"telegram","method":"sendMessage","mode":"reject"}` | Следующий такой вызов завершится сбоем. `mode`: `reject` — площадка отказала (статус «Ошибка»), `error500` — ошибка сервера площадки, `drop` — площадка приняла пост, но ответ не дошёл («Нужна проверка»). `"times": 3` — три вызова подряд |
| `POST /_emulator/reset` | Забыть всё опубликованное и все назначенные сбои |

Имена методов для `fault`: Telegram — `sendMessage`, `sendPhoto`, `editMessageText`, `editMessageMedia`; MAX — `POST messages`, `PUT messages`; ВКонтакте — `wall.post`, `wall.edit`, `messages.send`.

Имитатор повторяет то поведение площадок, на которое опирается сайт: Telegram не превращает текстовый пост в пост с фото и обратно и отвечает «message is not modified» на правку без изменений; ВКонтакте возвращает тот же пост на повторный `guid` и то же сообщение на повторный `random_id`. Картинки он отдаёт сам (`/images/<хост><путь>` — один и тот же PNG), поэтому ссылка на изображение в посте может вести на любой публичный адрес `https://`: наружу запрос не уходит.

## Что проверено на базе владельца 23.11.2026

Стенд на 42 723 товарах, четыре рабочих подключения к имитатору (WhatsApp — ручная задача):

- новый пост без фото и с фото — на трёх площадках; правка текста, смена типа, замена фото — на месте, без дублей;
- добавить фото к текстовому посту и убрать фото — ВКонтакте и MAX обновляются, Telegram показывает причину и кнопку «Изменить пост»;
- отказ Telegram → «Ошибка»; ошибка сервера ВКонтакте → повтор сам, один пост; потерянный ответ MAX и Telegram → «Нужна проверка», следующая правка ждёт; после «Пост есть — сохранить его ID» (номером или ссылкой) она меняет тот же пост;
- текст 3 862 символа; ссылка на изображение в локальной сети и подпись к фото длиннее 1 024 символов отклоняются при сохранении.
