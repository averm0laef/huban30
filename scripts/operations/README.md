# Первоначальная загрузка 1С

retire-one-c-initial-snapshot.sql — разовая операция по поручению владельца
28.11.2026 для снимка от 23.11 (initial-catalog.xml / initial-offers.xml).
Она снимает его товары с продажи, закрывает старые цены и списывает прежние
остатки с записью в журнал движения. ID и история остаются: обычный обмен
может принять GUID 1С по коду и восстановить актуальный товар с прежними
связями, адресом и фотографиями.

Перед production выполняется зашифрованный scripts/backup.sh с
AN30_COMPOSE_PROJECT=an30-production и COMPOSE_PROJECT_NAME=an30-production,
AN30_ENV_FILE=/etc/an30/production.env,
AN30_SECRETS_DIR=/etc/an30/production-secrets и AN30_APP_DIR текущего выпуска.
Отдельно проверяются размер и список файлов расшифрованного архива вложений.
SQL запускается в an30 через ключ SSH и psql -v ON_ERROR_STOP=1. Он проверяет происхождение
всех товаров, отсутствие новых прогонов, изменённых остатков, заказов и ручных
цен. Несовпадение прерывает всю транзакцию. Повтор после успешной операции
ничего не меняет, в том числе после поступления живых данных.

Проверка выполняется на отдельной пустой an30_cleanup_scratch_* со схемой
production без данных: one-c-retirement-fixture.sql →
retire-one-c-initial-snapshot.sql → verify-one-c-retirement.sql, затем повтор
последних двух файлов. Негативные прогоны с резервом, свежей ценой и новым
прогоном обмена должны отмениться целиком. Саму рабочую БД не используйте
как место для этих проверок.

В API runtime verify-one-c-retirement-recovery.mjs подаётся на stdin
node --input-type=module, с
AN30_RETIREMENT_TEST_DATABASE=an30_cleanup_scratch_…
Он проверяет реальный CommerceML поверх PostgreSQL: восстановление по коду,
GUID, прежний ID/URL/фото, новую цену и остаток. После этого SQL снятия
повторяется, а скрипт с AN30_RETIREMENT_VERIFY_ONLY=true проверяет, что
живые данные не были сняты повторно. В конце удаляется только созданная
проверкой scratch-БД.

После production-операции очищается кеш API пересозданием только контейнера
API из того же выпуска; перед этим убеждаются, что выгрузка 1С не идёт.
Проверяются нулевой опубликованный каталог без демонстрационных товаров,
HTTP/защита сайта, сохранность остальных данных и экраны 1440/768/375.
Полный каталог, цены и остатки возвращаются из настоящего обмена 1С.
