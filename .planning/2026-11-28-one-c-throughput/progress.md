## Фактическая причина 429

READ ONLY production: первичный каталог — 42723 товара, все one_c, external_id вида 00-…, source_version=1, созданы 23.11. Есть только два завершённых прогона initial-catalog.xml и initial-offers.xml (23.11), новых XML-прогонов нет. Временная загрузка one_c содержит 1198 файлов, 195009877 байт, последняя запись 27.11 12:13:06 UTC, XML отсутствуют. В журнале видны успешные checkauth и затем 429 file/checkauth. Зависших Redis-счётчиков нет.

Общий REQUEST_RATE_LIMIT=1200/60 учитывал checkauth + init + каждое изображение. Значит, следующий после 1198 файл блокируется, 1С прекращает обмен до XML. Регрессия с настоящими controller/service/session поверх тестовых Redis/БД воспроизвела failure «Слишком много запросов» на файле 1199 до исправления.

Исправление: сеанс проверяется до общего request budget. Подтверждённый cookie с актуальными IP/CIDR, ревизией, включением и двухчасовым сроком допускает поток init/file/import; ресурсы ограничены прежними 8 MiB/часть, 512 MiB/файл, 4 GiB/100000 файлов на базу, четырьмя ожидающими записями и одним импортом по 500 строк. До подтверждения сеанса и для Basic fallback без cookie сохранены 1200/60; checkauth 30/60. Бюджеты разделены по источнику и IP. Ошибка проверки сеанса даёт plain-text 503 без разрешения записи. Причина удаления счётчика с подтверждённой передачи зафиксирована здесь и будет в теле коммита по AGENTS.md, правило 4.

Добавлены проверки: 1250 файлов и затем XML товаров/предложений с ценами/остатками; работа подтверждённого сеанса при исчерпанном входном лимите; отзыв сеанса; раздельные бюджеты двух баз; 503 при отказе хранилища сеансов.
