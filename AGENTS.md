# АН-30 — заметки для агентов

Монорепозиторий: `apps/web` (Next.js 16, витрина и админка), `apps/api` (NestJS + Fastify), `apps/worker` (outbox: почта, Telegram/VK, поисковый индекс), `packages/contracts` (zod-контракты, общие функции), `packages/database` (миграции SQL), `packages/messaging`. Менеджер пакетов — `corepack pnpm`.

## Строгие правила (владелец, 24.11.2026)

Прошлые агенты ломали друг другу работу: коммитили чужое незаконченное, выкладывали без проверки, меняли решения владельца. Поэтому:

1. **Один агент на репозиторий.** Перед началом — `git fetch` и сверка с `origin/main`; чужие незакоммиченные правки не коммитить и не выкладывать без слова владельца.
2. **Согласование до работы.** Изменения интерфейса — сначала макет в Claude Design (холсты в памяти проекта), потом код. Решения о лимитах, лицензиях (UMAPI, TecDoc, Rossko, FAPI) и о хранении данных поставщиков меняет только владелец; решение записывается в документ с датой.
3. **Выкладка на сервер — только по слову владельца в чате.** До запуска сайт закрыт паролем (`SITE_PASSWORD_ENABLED=true`, хеш — `secrets/site_password_hash.txt`); не открывать. На сервер — только по SSH-ключу, вход по паролю агентам запрещён.
4. **Ничего не убирать молча.** Удаление поведения (доступность, «уменьшенная анимация», защита от двойного нажатия, проверки) — только с причиной в теле коммита.
5. **Проверка перед коммитом:** `lint`, `typecheck`, `test`, сборка сайта. После правок шапки, поиска, меню и карточки — `scripts/storefront-checks/mobile-webkit.mjs` (iPhone на WebKit) и `catalog-menu.mjs`; снимки 1440 / 768 / 375.
6. **Покупателю — только русский текст** без названий поставщиков, ключей и лимитов; на месте фото товара — не фото другой детали.
7. **Журнал.** Каждая задача — запись в `CHANGELOG.md` и в `.planning/<дата-задача>/progress.md`: что сделано, чем проверено, что не сделано.

## Проверка

```bash
corepack pnpm lint
corepack pnpm typecheck        # сначала собирает contracts и messaging
corepack pnpm test
corepack pnpm --filter @an30/web build
```

Реальный регрессионный набор поиска (188 запросов) — на отдельной пустой БД:

```bash
createdb an30_search_scratch
DATABASE_URL=postgresql://localhost/an30_search_scratch DATABASE_ENVIRONMENT=development node packages/database/dist/migrate.js up
CATALOG_SEARCH_DATABASE_URL=postgresql://localhost/an30_search_scratch corepack pnpm --filter @an30/api exec vitest run src/catalog/catalog-search-regression.test.ts
dropdb an30_search_scratch
```

После правок в `packages/contracts` пересоберите его (`corepack pnpm --filter @an30/contracts build`): API и сайт читают `dist`.

Проверки витрины, которых не дают снимки экрана (меню «Каталог» движением мыши и клавиатурой; запросы сайта к API на одного посетителя) — `scripts/storefront-checks/README.md`. Запускайте после правок шапки, меню и чтения каталога на сайте.

Замеры поиска на ассортименте владельца (разговорные запросы; товары с сокращениями в названии) — `scripts/search-checks/README.md`. Запускайте после правок поиска и таблицы сокращений словаря деталей: регрессионный набор идёт на двух сотнях товаров-образцов и не видит того, что видно на 42 тысячах.

Сквозные тесты (`corepack pnpm test:e2e`) идут на сайте без API. На 22.11.2026 семь из девятнадцати не проходят (чат, поиск по VIN, подтверждение регистрации, настройка подключений) — они отстали от сайта и не разобраны; не принимайте их падение за последствие своей правки, не сверившись с этим списком.

## Правила проекта

- Дизайн: цвета логотипа (#1800E0, #140F57, жёлтый #F5C400), Montserrat в заголовках; без «ИИ-шаблонов» (иконки в цветных плитках, градиентные пятна, акцентные полосы слева). Для любых изменений интерфейса — скилл `ui-ux-pro-max` как чек-лист (цели 44 px, текст ≥ 12 px, контраст, reduced motion); его палитры и шрифты не применять.
- Каждое изменение интерфейса проверяйте скриншотами на 1440, 768 и 375 px: без наложений и горизонтальной прокрутки. Снимок не видит поведения: всё, что открывается наведением, проверяйте движением мыши шагами (а не `hover()`, который переносит её мгновенно) и клавиатурой.
- Платные провайдеры (FAPI, TecDoc, ReefAPI, Apify, Groq) в тестах не вызываются — только подставные ответы.
- Справочник машин UMAPI (`app.vehicle_catalog_*`) хранится в нашей базе по лицензии владельца; выбор машины идёт только из него и не тратит запросов платных каталогов. Загрузка, обновление и устройство — `docs/UMAPI.md`; файл лежит в `local-data/umapi/` и в Git не попадает.
- Каталог запчастей по машине — свой, внутри «Подбора» (решение владельца 24.11.2026; виджет UMAPI не ставить, дизайн витрины и каталога товаров не переделывать). Запросы к UMAPI — только по действию посетителя и через `UmapiGateway` (кеш, бюджет, пауза при отказе); не больше 10 страниц `Articles` на раздел и не больше трёх одновременно; списки деталей каталога по машине в PostgreSQL не писать. Кроссы UMAPI (ответы `Analogs`) пишутся в `app.article_crosses` как неподтверждённые, источник `umapi` (решение владельца 24.11.2026, `docs/UMAPI_INTEGRATION.md`, раздел 10); подтверждает пару второй источник (Rossko, 1С, FAPI) или сотрудник. Поиск «деталь + машина» читает только наш справочник машин — платный каталог при наборе не спрашивать. Устройство и расход — `docs/UMAPI_INTEGRATION.md`, раздел 9. Список марок масел с фото в каталоге (`UMAPI_FLUID_MAKERS`) менять только по новому замеру.
- TecDoc (tecdoc.site): только «запрос — ответ» для посетителя. Нельзя писать его данные в PostgreSQL (в том числе в `app.article_crosses`), вызывать его из фоновых задач и увеличивать кеш без письменного согласия поставщика — см. `docs/TECDOC.md`.
- Картинки разделов и подкатегорий (`apps/web/public/categories/<slug>.webp`, поле `image` в `storefront-taxonomy.ts`) — одна объёмная деталь в фирменном синем с серебром на прозрачном фоне, 512×512, без текста и логотипов. Новые рисовать в том же стиле (24.11.2026 — Codex `image_gen` с образцами `podveska`, `tormoznye-kolodki`); у каждой подкатегории своя картинка, не картинка раздела.
- Разделы каталога и сортировка товаров из 1С — `docs/OWN_CATALOG.md`; при изменении `storefront-taxonomy.ts` нужна миграция с теми же строками.
- Описание подбора — `docs/PARTS_FINDER.md`, обмена с 1С — `docs/ONE_C_INTEGRATION.md`, поиска — `docs/SEARCH_ENGINE.md`, хранения фото товаров в S3 — `docs/PRODUCT_PHOTOS_S3.md`, источников фото и снятия их с сайта — `docs/PRODUCT_PHOTOS.md` (картинки с чужих сайтов не собирать).
