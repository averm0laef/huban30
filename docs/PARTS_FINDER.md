# Подбор по автомобилю и VIN

Страница `/podbor` и поиск в шапке. Покупатель пишет деталь и машину («топливный фильтр Toyota Gaia», с опечатками и в неверной раскладке), выбирает машину из списка «марка → модель → двигатель» или вставляет VIN / японский номер кузова. Сайт уточняет модификацию, называет подходящие артикулы и показывает товары АН‑30 с ценой и остатком: по точному артикулу и по кроссам.

> С ключом TecDoc (tecdoc.site) каталог машин, детали для машины и применимость берутся из него — см. [TECDOC.md](TECDOC.md). Без ключа или при его отказе работает всё описанное ниже. Разделы каталога и сортировка товаров из 1С — [OWN_CATALOG.md](OWN_CATALOG.md).

## Как устроено

Логика модуля владельца (исходник — `services/parts-finder`, Python) перенесена в API и работает внутри него: `apps/api/src/parts-finder`.

```
браузер ── /api/v1/parts-finder/* ──▶ NestJS API (parts-finder)
                                       ├─ разбор фразы: опечатки, раскладка, транслит      (engine/part-query.ts)
                                       ├─ локальная применимость (Probox, импорт CSV)     (app.parts_fitment)
                                       ├─ FAPI: каталог машин, детали модификации, кроссы (engine/fapi*.ts)
                                       ├─ VIN: правила LADA, NHTSA vPIC, VINROKU (кузов)   (engine/vin-decoder.ts)
                                       └─ PostgreSQL АН‑30: товары, цены, остатки, кроссы (app.article_crosses)
```

Маршруты (`/api/v1/parts-finder`): `status`, `resolve` (единый вход поиска в шапке), `search` (пошаговый подбор), `vehicle` (VIN), `crosses` (карточка FAPI по артикулу), `shop-analogs` (только наша база, бесплатно), `makes`, `models`, `modifications`, `vehicles/suggest`. Для персонала (право `catalog:write`): `GET /staff/parts-finder/usage`, `GET /staff/parts-finder/overview`, `GET /staff/parts-finder/vehicles`, `POST /staff/parts-finder/vehicles/sync`.

## Как подбор связан с каталогом

1. Каждая найденная деталь получает поле `shop`: товары АН‑30 по точному артикулу (`matchedVia: "exact"`) и по подтверждённым кроссам (`matchedVia: "cross"`). Первыми идут детали, которые есть в наличии.
2. Если ни одного подходящего артикула у нас нет, API запрашивает карточки FAPI для первых пяти артикулов (по 1 кредиту, повтор из кеша бесплатно). Найденные кроссы сохраняются в `app.article_crosses` (источник `fapi`), после чего наш каталог проверяется ещё раз. Так покупатель видит аналог из наличия, а база кроссов растёт с каждым подбором.
3. Подтверждёнными сразу становятся номера производителя машины (OE), замены и аналоги, которые подтвердил сам производитель. Остальные аналоги ждут подтверждения сотрудником, как кроссы поставщика.
4. Карточки FAPI по кнопке «Аналоги» сохраняются в базу так же.
5. Если подбор не дал артикулов, кнопка ведёт в раздел каталога этой детали (например, «Топливные фильтры») с пометкой о выбранной машине, а не в текстовый поиск.

Полная схема «номер покупателя → наш товар» (личность бренда, связывание ассортимента, уровни доверия к кроссам) — в [CATALOG_MATCHING.md](CATALOG_MATCHING.md).

Названия машин на русском («гайя», «вокси», «на короллу», «чайзер») читаются через сам справочник машин: звучание русского слова сравнивается со звучанием названия модели, марка добавляется сама. Слова деталей и бренды, которые мы продаём («гайка», «патрон», «сакура»), машинами не становятся.

## Кеш и расход кредитов FAPI

- Ответ FAPI хранится в PostgreSQL (`app.parts_finder_fapi_cache`) **30 дней** на платном тарифе; пустой ответ — сутки. Кеш общий: он переживает перевыпуск ключа и смену расчётного периода. Одинаковые одновременные запросы делают один платный вызов, похожие артикулы (`04152-40060` и `0415240060`) — один ключ кеша.
- На **пробном** тарифе (trial) кеш живёт 5 минут — таковы условия пробного доступа.
- Дневной лимит `FAPI_DAILY_CREDIT_LIMIT` считается по Москве на все экземпляры API; при нехватке остатка пакета новые запросы останавливаются, кеш продолжает отвечать.
- Доля одного посетителя `FAPI_VISITOR_DAILY_CREDIT_LIMIT` (по умолчанию 100 кредитов в московские сутки) считается в Redis по хешу адреса; сам адрес не хранится, счётчик исчезает через сутки. Раньше один адрес мог за две-три минуты потратить дневной лимит всего сайта (60 списков двигателей в минуту по 8 кредитов). Доля берётся только при настоящем платном вызове: ответ из кеша бесплатен; пустой ответ каталога стоит 1 кредит, отказ FAPI возвращает всё. Когда доля кончилась, подбор отвечает этому посетителю по данным магазина — слов про кредиты он не видит. Работа самого магазина (синхронизация справочника машин, связывание ассортимента) долей не ограничена: в коде плательщик передаётся явно (`FapiPayer`: адрес посетителя или `null`), см. `parts-finder.engine.ts`.
- Цены: карточка кроссов — 1 кредит, список моделей марки — 8, список модификаций модели — 8, полный подбор по машине — около 24–35 кредитов при первом запросе, повтор — 0.
- Расшифровки VIN (vPIC) и номеров кузова (VINROKU) кешируются на 30 дней.

## Справочник машин

Марки — выверенный список (`engine/vehicle-seed.ts`, около 95 марок): сначала японские, затем европейские, затем остальной рынок РФ. Модели с годами выпуска и модификации с кодом двигателя берутся из каталога FAPI (данные TecDoc) и хранятся в `app.parts_finder_vehicle_*`. Мотоциклы, скутеры и совместные предприятия из полного списка FAPI (1 245 брендов) намеренно не подключаются.

Заполнение: админка → «Настройки» → «Подбор и поставщики» → «Обновить справочник из FAPI». Фоновая задача за один запуск тратит не больше 1 500 кредитов: связывает марки с FAPI, загружает модели всех марок, затем модификации популярных марок (выпуск с 1995 года). Сначала загружаются японские марки, затем европейские. Список моделей марки обновляется раз в 90 дней; двигатели поколения, снятого с производства, оплачиваются один раз. Марка без моделей в списке выбора не показывается.

## Выбранная машина: где она видна и где хранится

- **На устройстве.** Машина, выбранная на `/podbor`, хранится в браузере (`localStorage`, функции `readPickedVehicle` / `savePickedVehicle` в `apps/web/app/(store)/_lib/parts-finder.ts`); машина, известная только строкой (набрана текстом или прочитана из VIN), — там же (`readSavedVehicle`). Обе читает `readChosenCar`.
- **В шапке на каждой странице.** Третье действие рядом с «Корзиной» и «Войти» (`_components/header-vehicle.tsx`, `HeaderVehicle`): без машины — «Выбрать авто», с машиной — марка и модель; полное описание — в подсказке и для программ чтения с экрана. Место занято всегда и одной ширины: машина известна только после чтения хранилища браузера, и действие, которое появлялось бы после загрузки, сдвигало бы поле поиска при каждом открытии страницы. Уже 1180 px остаётся один значок — подпись отнимала бы ширину у поля поиска. Ведёт на `/podbor`.
- **На телефоне** — строкой в выдвижном меню (`DrawerVehicle`), под блоком входа.
- **В гараже личного кабинета** (`app.customer_vehicles`, `apps/api/src/garage`): кнопка «Сохранить в гараж» в карточке машины на `/podbor` есть у вошедшего покупателя и с каталогом TecDoc, и без него — гараж принимает машину собственного справочника (`catalog: { modelId, modificationId }`). Условие показа — чистая функция `vehicleCardActions` (раньше кнопка лежала внутри блока, который рисуется только при TecDoc, и без ключа не показывалась).
- **Основная машина гаража** подтягивается вошедшему покупателю, который не выбирал машину на этом устройстве: шапка спрашивает гараж один раз за сеанс браузера (`useChosenCar`), а не на каждой странице.

Проверки: `_lib/parts-finder-vehicle-card.test.ts` (8 тестов). Поведение в браузере проверялось скриптами с подставными ответами гаража (кнопка, тело запроса, шапка на пяти ширинах, выдвижное меню); настоящая запись в гараж через вход покупателя на стенде не проверялась.

## Настройки

Ключи локально лежат в `secrets/parts_finder.env` (dotenv), в Docker — в секрете `parts_finder_env`.

| Ключ | Значение |
| --- | --- |
| `FAPI_KEY` / `FAPI_KEY_FILE` | ключ FAPI; без него работают разбор фразы, локальная применимость и VIN |
| `FAPI_FITMENT_ENABLED` | `1` — подбор машины через FAPI (список деталей модификации), `0` — только локальный справочник |
| `FAPI_DAILY_CREDIT_LIMIT` | дневной лимит кредитов, по умолчанию 1000 |
| `FAPI_VISITOR_DAILY_CREDIT_LIMIT` | сколько кредитов в сутки может потратить один посетитель (по адресу), по умолчанию 100 |
| `API_NINJAS_KEY`, `API_NINJAS_MODE` | запасная расшифровка VIN, необязательно |
| `PARTS_FINDER_ENABLED` | `false` выключает подбор целиком |

Лимиты на один IP: поиск и `shop-analogs` — 30 в минуту, VIN — 20 в минуту, кроссы — 6 за 10 минут, справочник — 60 в минуту.

## Импорт своей применимости

UTF‑8 CSV, начальные нули сохраняются, набор заменяется одной транзакцией:

```
make,model,category,configuration,engine,liters,year_from,year_to,article,brand,oem,source
```

```bash
node apps/api/dist/cli/parts-fitment-import.js fitment.csv --dry-run   # проверка
node apps/api/dist/cli/parts-fitment-import.js fitment.csv             # загрузка
```

## Что решает владелец

1. Платный пакет FAPI. Текущий ключ из модуля auto-vin — пробный: 500 кредитов, на 21.11.2026 осталось 5. Для работы подбора и наполнения справочника нужен пакет на 30 000 кредитов в месяц; новый ключ кладётся в `secrets/parts_finder.env`.
2. Оставить ли автоматическое подтверждение OE-кроссов и замен из FAPI или подтверждать всё вручную.
3. Нужны ли Autodoc (ReefAPI), Car-Part и подсказки Groq: сейчас сайт их не использует.
