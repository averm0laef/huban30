# Аудит legacy-проекта

Дата фиксации: 2026-07-31, Asia/Chita.

## Объём и архитектура

- React 18, Vite, Tailwind CSS 3, shadcn/Radix и Supabase.
- Около 34 876 строк исходного кода.
- 17 публичных страниц, 20 административных страниц и около 50 UI-компонентов.
- 31 таблица, 3 storage bucket, 39 миграций и 18 Supabase Edge Functions.
- 125 прямых обращений фронтенда к Supabase.

## Найденные проблемы

- Git отсутствовал, `.env` не был исключён из индексации.
- Одновременно присутствовали `package-lock.json`, `bun.lock` и `bun.lockb`.
- `package.json` и npm lock-файл рассинхронизированы, чистый `npm ci` не проходил.
- Аудит зависимостей показал 11 известных уязвимостей: 10 high и 1 moderate.
- В legacy-функциях использовался открытый CORS и для ряда функций была отключена проверка JWT.
- В исходниках были жёстко заданы данные администратора, fallback-секрет и слабое значение пароля 1С по умолчанию.
- Административный интерфейс мог получать и показывать пароль обмена 1С.
- В логах встречались токены, auth-данные и PII.
- Runtime-код зависел от Supabase, Lovable AI и URL `an30.lovable.app`.

## Проблемы интерфейса

- На главной отсутствовал настоящий `h1`.
- Каталог и показатели показывали пустые или вечные loading-состояния.
- Мобильные подписи обрезались, метаданные страниц не были уникальными.
- Присутствовали непроверенные показатели и отзывы.
- Требуется сохранить существующую навигацию, URL, логотип и сине-жёлтые brand-токены.

## Команды повторной проверки

```bash
rg -n --hidden -g '!node_modules/**' 'supabase|lovable' .
rg -n --hidden -g '!node_modules/**' 'Access-Control-Allow-Origin' supabase/functions
rg -n --hidden -g '!node_modules/**' 'password|secret|token' supabase src
find . -maxdepth 1 -type f -name '*lock*' -print
pnpm verify
```

`pnpm verify` появится в AN30-003. До этого этапа отсутствие команды считается известным ограничением.
