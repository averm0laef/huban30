# Стратегия каталога без TecDoc

## Решение

До появления лицензии TecDoc сайт ищет товар только в двух источниках:

1. собственный ассортимент, цены и остатки из 1С;
2. предложения Rossko по артикулу или артикулу с брендом.

Сайт не копирует каталог Exist и не обещает совместимость детали с автомобилем, если связь не подтверждена лицензированным каталогом производителя или сотрудником магазина. Правила Exist запрещают массовые выборки и коммерческое переиспользование материалов без разрешения правообладателя: [ограничения](https://www.exist.ru/About/Legal/Limits), [правила использования](https://www.exist.ru/About/Legal/Rules).

Это не временная заглушка. Это безопасная модель, в которой цена, наличие и происхождение каждого результата понятны покупателю.

## Пользовательский поиск

Одна строка принимает:

- точный или частичный артикул;
- артикул вместе с брендом;
- название детали;
- VIN или номер кузова для заявки на проверку сотрудником.

Порядок ответа:

1. Нормализовать пробелы, регистр и допустимые разделители артикула.
2. Показать точные совпадения своего склада из 1С.
3. Показать подтверждённые аналоги своего склада с явной меткой «Аналог».
4. Запросить Rossko и вывести предложения отдельным источником «Под заказ».
5. Если надёжного совпадения нет, предложить заявку по VIN, не подменяя её фиктивной выдачей.

Rossko рекомендует искать по артикулу или по сочетанию артикула и бренда. Поиск по свободной фразе остаётся запасным сценарием и не должен считаться проверкой применимости: [официальная документация GetSearch](https://api.rossko.ru/index.php?action=SOAP&path=%2FGetSearch).

## Каталог автомобилей

Справочник автомобилей и товарные предложения должны быть разделены. Наличие марки или модели в справочнике ещё не означает, что конкретная деталь подходит этому автомобилю.

Минимальная модель данных:

- `vehicle_makes`: марка, альтернативные написания, рынок;
- `vehicle_models`: модель, поколение, годы выпуска;
- `vehicle_modifications`: кузов, двигатель, привод и трансмиссия;
- `product_fitments`: товар, модификация, источник связи, статус проверки, дата и сотрудник;
- `vin_requests`: VIN или номер кузова, контакт, результат проверки и срок хранения данных.

Статусы связи товара с автомобилем:

- `verified`: подтверждено каталогом производителя или сотрудником;
- `candidate`: импортировано из разрешённого источника и ждёт проверки;
- `rejected`: проверено и отклонено.

Покупателю показывается совместимость только для `verified`. `candidate` используется лишь во внутренней очереди администратора.

Бесплатный vPIC NHTSA можно использовать как вспомогательный источник марок, моделей и декодирования части VIN. Он не содержит универсальных связей деталей с автомобилями и не заменяет TecDoc, особенно для российского и японского парка: [официальное API vPIC](https://vpic.nhtsa.dot.gov/api/).

## Источники данных

Разрешены:

- 1С владельца магазина;
- официальный Rossko API в пределах договора и лимитов;
- файлы производителей и поставщиков, на которые у магазина есть право использования;
- вручную загруженные администратором CSV/XLSX с зафиксированным происхождением;
- открытые данные, лицензия которых разрешает коммерческое использование и публикацию производных данных.

Для каждого импорта сохраняются источник, версия, дата, контрольная сумма, результат проверки и возможность отката. Данные без понятной лицензии не загружаются.

## Полезные фильтры

Фильтр добавляется только тогда, когда он сужает реальные товары:

- категория;
- бренд;
- наличие: в магазине или под заказ;
- диапазон актуальной цены;
- срок поставки, когда поставщик вернул подтверждённый срок;
- сторона установки, размеры и другие характеристики только из утверждённых публичных атрибутов 1С.

Не следует создавать пустые фильтры по марке, модели и году до появления проверенных `product_fitments`. Такой интерфейс выглядит наполненным, но вводит покупателя в заблуждение.

## Этапы внедрения

### Сейчас

- довести CommerceML до стабильной загрузки категорий, брендов, товаров, цен и остатков;
- сделать устойчивый объединённый поиск своего склада и Rossko;
- добавить реальные фильтры бренда, цены и наличия;
- собирать неподтверждённые кроссы в очередь ручной проверки;
- обрабатывать VIN как заявку сотруднику.

### После загрузки данных владельцем

- проверить реальные `import.xml` и `offers.xml` на тестовом контуре;
- сопоставить атрибуты 1С с публичными фильтрами;
- включать фильтр только при достаточном количестве заполненных значений;
- сформировать отчёт по товарам без бренда, категории, цены, остатка и изображения.

### После получения легального источника применимости

- загрузить справочник автомобилей отдельно от товаров;
- импортировать связи в статус `candidate`;
- проверить выборку вручную;
- открыть подбор по автомобилю только после достижения согласованного порога качества.

## Критерии готовности

- результат всегда помечен источником: «В магазине», «Аналог» или «Под заказ»;
- цена Rossko содержит торговую наценку и не раскрывает закупочную цену;
- ошибка поставщика не превращается в сообщение «ничего не найдено»;
- одинаковый запрос не создаёт каскад повторных SOAP-вызовов;
- совпадение артикула без бренда не подтверждает кросс автоматически;
- ни одна страница не заявляет совместимость без проверенного источника;
- все импорты и ручные подтверждения имеют журнал и возможность аудита.
