# Рабочее место персонала

Автономная админ-панель доступна по `/admin`. Она использует только same-origin REST `/api/v1` и WebSocket `/ws`; браузер не подключается к PostgreSQL и не содержит административных ключей.

## Роли и разделы

| Раздел | Менеджер | Директор | Администратор |
| --- | --- | --- | --- |
| Сводка, заказы и накладные | Да | Да | Да |
| Чаты и назначения | Да | Да | Да |
| Каталог и импорт 1С | Да | Да | Да |
| Персонал | Нет | Просмотр | Просмотр и приглашение |
| Отчёты | Нет | Да | Да |
| Настройки 1С и аудит | Нет | Нет | Да |

Меню отражает матрицу для удобства, но источником прав является NestJS API. Прямой запрос без разрешения возвращает `403`. Сотрудник получает права только после пароля, обязательного TOTP и ротации opaque-сессии.

## Рабочие сценарии

- Сводка показывает только фактические очереди PostgreSQL; оборот доступен директору и администратору.
- Заказы имеют серверные фильтры, сортировку, пагинацию, массовый переход на следующий этап и optimistic version. Карточка читает неизменяемые снимки контактов, доставки, состава и цены. Отмена неоплаченного заказа освобождает резерв. Возврат передаётся целыми копейками и требует явного подтверждения.
- Чат восстанавливает историю из PostgreSQL, после чего получает realtime-события через `/ws`. Сообщения дедуплицируются по ID. Менеджер может назначить чат только себе или снять своё назначение; закрытый чат повторно открывает только директор или администратор.
- Каталог показывает текущую применённую цену, доступный остаток и версию 1С. Ручная подмена цены из браузера отсутствует.
- Импорт 1С показывает все состояния batch, первые 50 строк server-side preview, ошибки и отчёт конфликтов. Apply и rollback требуют отдельного подтверждения.
- Накладная создаётся по заказу; сумму рассчитывает сервер. Для одного заказа разрешена одна действующая накладная. Выдача и аннулирование защищены optimistic version.
- Настройки 1С не возвращают пароль в браузер и предупреждают о несохранённых изменениях. Аудитный список намеренно не передаёт before/after, metadata, IP и user-agent.

## Интерфейс

Рабочее место использует Fluent UI и TanStack Table. Дизайн намеренно плотный и утилитарный: постоянная навигация, настоящие таблицы и явные loading, empty, error, offline, conflict, confirmation и unsaved states. Поддерживаются светлая и тёмная темы, клавиатурная навигация, skip-link, мобильное меню и `prefers-reduced-motion`. Декоративная 3D-графика и Blender здесь не применялись, поскольку не улучшают рабочую операцию.

## Проверка

```bash
pnpm --filter @an30/web test
pnpm --filter @an30/web typecheck
pnpm --filter @an30/web lint
pnpm --filter @an30/web build
pnpm --filter @an30/api test
pnpm --filter @an30/api typecheck
pnpm --filter @an30/api build
```

После запуска Compose расширенный `staff-auth:smoke` выполняет 33 HTTP-проверки: MFA владельца и менеджера, доступные и запрещённые разделы, self-assignment, запрет назначения другому сотруднику, optimistic conflict, закрытие и повторное открытие чата. Миграция `0013_staff_workspace.sql` добавляет версии чатов/накладных и атомарную последовательность номеров.

В текущей Codex-песочнице сетевой bind и доступ к Docker socket запрещены, поэтому browser/Compose smoke этой итерации необходимо повторить на staging. Это ограничение среды проверки, а не разрешение пропустить production E2E.
