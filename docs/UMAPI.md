# UMAPI: справочник машин

Сайт уходит от TecDoc (tecdoc.site) к UMAPI. Владелец купил у UMAPI архив справочника легковых машин (`cb_passenger_cars.csv`) официально, вместе с правом хранить его в своей базе. API UMAPI (кроссы, применимость) будет куплен отдельно.

**Главное:** выбор машины — марка, модель, поколение, двигатель — идёт из нашей базы и не тратит ни одного запроса к UMAPI, TecDoc или FAPI. Запросы к API UMAPI пойдут только на кроссы и применимость.

Проверка совместимости, аналоги и идентификация деталей через API UMAPI — [UMAPI_INTEGRATION.md](UMAPI_INTEGRATION.md).

Лицензию (договор, счёт или письмо с условиями) владелец хранит у себя. Правило AGENTS.md «данные TecDoc в PostgreSQL не писать» относится к tecdoc.site и к этому справочнику не относится.

## Что в файле

- 90 658 модификаций, 736 марок, 16 096 моделей и поколений, годы по 2026-й включительно.
- Формат: разделитель — двоеточие, значения в кавычках, пустое значение — `NULL`, кавычка внутри удваивается.
- Расхождения внутри файла: у части моделей русское и английское название, дата окончания `1970-01-01` вместо «неизвестно». Разборщик берёт значение большинства строк. Подробности — в `packages/database/src/vehicle-catalog-csv.ts`.
- Деталей, кроссов, применимости и VIN в файле нет.

## Таблицы

Миграция `0056_vehicle_catalog.sql`:

| Таблица | Что хранит |
|---|---|
| `app.vehicle_catalog_makes` | марки |
| `app.vehicle_catalog_models` | модели и поколения (`name`, `short_name`, `series`, годы) |
| `app.vehicle_catalog_modifications` | модификации: объём, мощность, топливо, привод, кузов, годы |
| `app.vehicle_catalog_imports` | журнал загрузок: файл, sha256, что изменилось |

Особенности:
- Номера записей начинаются со 100 000 001, а `umapi_id` — номер записи в файле UMAPI.
- Запись, которой нет в новом файле, получает `is_active = false` и не удаляется: на неё могут ссылаться гаражи покупателей.
- Прежний справочник из FAPI (`app.parts_finder_vehicle_makes`, `_models`, `_modifications`) удалён миграцией `0057`. Кеш VIN `app.parts_finder_vehicle_cache` остался.

## Как загрузить или обновить

Файл хранится в `local-data/umapi/` и в Git не попадает.

Проверить файл, не трогая базу:

```bash
node packages/database/dist/import-vehicle-catalog.js local-data/umapi/cb_passenger_cars.csv --dry-run
```

Загрузить:

```bash
DATABASE_URL=… DATABASE_ENVIRONMENT=development node packages/database/dist/import-vehicle-catalog.js local-data/umapi/cb_passenger_cars.csv
```

Как работает загрузка:
- **Одна транзакция:** сломанный файл ничего не меняет.
- **Повторная загрузка того же файла ничего не меняет.**
- **Защиты:**
  - файл меньше 1 000 модификаций не загружается;
  - файл, который скрыл бы больше 10% модификаций, загружается только с флагом `--allow-retire`.
- **Время:** около 3 секунд на 90 тысяч строк.

**На сервере** загрузку нужно запустить сразу после миграций. До неё выбор машины показывает «Список автомобилей пока не загружен».

1. Скопировать файл на сервер.
2. Запустить ту же команду в контейнере миграций (у него есть доступ к базе от имени владельца), подключив файл томом:

```bash
docker compose run --rm -v /путь/cb_passenger_cars.csv:/data/cars.csv:ro migrate node dist/import-vehicle-catalog.js /data/cars.csv
```

Размер справочника и сведения о последней загрузке видны в админке: «Подбор и поставщики» → «Справочник автомобилей UMAPI».

## Как сайт его читает

Вся работа с данными — в `apps/api/src/parts-finder/`:

- **`vehicle-catalog.service.ts`**:
  - марки, модели, двигатели;
  - подсказки при вводе: по-русски, латиницей, в неверной раскладке, по коду кузова («corolla e12»);
  - машина для подбора деталей.
- **`vehicle-catalog.logic.ts`** — как показывать:
  - название марки — из списка магазина `vehicle-seed.ts`;
  - модель, как её называют: «Land Cruiser 80» относится к Land Cruiser, а Corolla Cross — отдельная модель;
  - серия и код кузова — отдельно;
  - строка двигателя: «1.4 л VVT-i (ZZE120, ZZE120R)», мощность, топливо, привод.
- **`parts-finder-vehicles.service.ts`** — тонкая обёртка для маршрутов `/parts-finder/makes|models|modifications|vehicles/suggest`. Там же словарь машин для чтения поискового запроса. В словарь берутся только марки из списка магазина, чтобы «газель» оставалась ГАЗом, а не редкой маркой Hillman.
- **`/parts-finder/status`** отвечает `catalog: "umapi"`. TecDoc отвечает за машины, только пока справочник не загружен, а ключ TecDoc задан.

Машина, выбранная в старом списке до перехода (номер меньше 100 000 001):
- сайт сохраняет её название и сбрасывает номера;
- поиск читает машину по названию;
- покупатель выбирает её заново, когда захочет.

## Интерфейс

Дизайн нарисован на холсте Claude Design «АН-30 — выбор автомобиля и „Мои автомобили“» (ссылка — в журнале `.planning/2026-11-23-umapi-vehicle-catalog/progress.md`).

- **Меню выбора** (`apps/web/app/(store)/podbor/vehicle-picker.tsx`):
  - четыре шага с номерами;
  - четыре выпадающих списка «Марка → Модель → Поколение → Двигатель» — для тех, кому так проще;
  - под ними карточки: популярные марки с русскими названиями, все марки по первой букве, модели, поколения с плашками «Кузов E12» и «Седан», двигатели строками по топливу с мощностью справа.
- **Итог «Ваш автомобиль»** на `/podbor`: плашки «Поколение», «Тип кузова», «Двигатель», «Мощность», «Топливо», «Привод», «Выпуск».
- **«Мои автомобили»** в кабинете (`garage-panel.tsx`): карточка на машину, бейдж «Основной», характеристики плашками, кнопки «Подобрать запчасти» и «Сделать основным».
