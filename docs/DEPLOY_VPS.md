# Установка сайта АН-30 на сервер (VPS)

Сейчас сайт на сервере **не установлен**. Этот документ описывает, что
владелец должен подготовить заранее и в каком порядке сайт ставится на чистый
сервер. Первая часть написана для владельца. Команды из разделов 3–12
выполняет разработчик или администратор.

Связанные документы (здесь они не повторяются):

- [OPERATIONS.md](OPERATIONS.md): обновление, откат, резервные копии,
  восстановление, наблюдение, действия при сбоях. Написан для закрытого
  тестового сервера (staging); отличия для рабочего сайта указаны ниже.
- [ONE_C_SETUP_UNF.md](ONE_C_SETUP_UNF.md): настройка обмена в 1С.
- [AUTHENTICATION.md](AUTHENTICATION.md): учётные записи, первый владелец.
- [PRODUCTION_LEGAL_CHECKLIST.md](PRODUCTION_LEGAL_CHECKLIST.md): что нужно
  утвердить, прежде чем открывать приём заказов.
- [PARTS_FINDER.md](PARTS_FINDER.md): подбор по автомобилю и ключ FAPI.
- [SECRET_ROTATION.md](SECRET_ROTATION.md): какие старые пароли и ключи нужно
  заменить.

## 1. Что нужно от владельца до установки

| Что | Подробности |
| --- | --- |
| Сервер (VPS) | Ubuntu 24.04 LTS. Не меньше 4 ядер, 8 ГБ памяти и 100 ГБ диска NVMe (в журнале проекта для рабочего сайта рекомендовано 120 ГБ). Нужен постоянный внешний адрес IPv4. Меньше 8 ГБ нельзя: одному только антивирусу, который проверяет загружаемые файлы и фото, нужно 2–3 ГБ. |
| Доступ к серверу | Вход по SSH по ключу для пользователя с правом `sudo`. Пароль от сервера в переписку не отправляйте. |
| Домен | Имя сайта и доступ к управлению DNS. Нужна запись типа A: `<домен>` → адрес сервера. По желанию вторая запись A для `www.<домен>`. Запись должна заработать **до** первого запуска: сервер сам получает сертификат HTTPS, и для этого домен уже должен вести на него. |
| Почтовый ящик сайта | Адрес отправителя, сервер исходящей почты (SMTP), порт, логин и пароль. Обязательно защищённое соединение: порт 587 (STARTTLS) или порт 465 (SSL). Без почты не уходят письма подтверждения регистрации, восстановления пароля и приглашения сотрудников. Уточните у хостинга сервера, не закрыта ли на нём исходящая почта. |
| Ключ FAPI (платный) | Нужен для подбора по автомобилю и поиска аналогов. По [PARTS_FINDER.md](PARTS_FINDER.md) прежний ключ пробный и почти исчерпан; нужен платный пакет. Без ключа подбор работает в сокращённом виде. |
| Ключи поставщика | Rossko: два ключа (KEY1 и KEY2). Без них поиск «под заказ» у поставщика выключен, остальное работает. |
| Яндекс ID | Идентификатор приложения (Client ID). В кабинете Яндекс ID укажите адрес возврата `https://<домен>/api/v1/auth/social/yandex/callback` и доступ `login:info`. |
| VK ID | Идентификатор приложения (ID). В кабинете VK ID укажите адрес возврата `https://<домен>/api/v1/auth/social/vk/callback`. |
| Адрес почты владельца | На него создаётся первая учётная запись администратора. |
| Телефон с приложением для одноразовых кодов | Вход сотрудников требует второй шаг (TOTP): «Яндекс Ключ», Google Authenticator или похожее приложение. |
| Адрес (IP) вашей 1С | С какого адреса 1С выходит в интернет. См. [ONE_C_SETUP_UNF.md](ONE_C_SETUP_UNF.md), раздел 4. |

Яндекс ID и VK ID не обязательны: без них кнопки входа через эти сервисы
просто не показываются. Секретные ключи приложений для них не нужны, только
идентификаторы.

Необязательные подключения, для которых тоже понадобятся ключи, если вы ими
пользуетесь: уведомления сотрудникам в Telegram (токен бота и номер чата) и
во «ВКонтакте» (токен и номер беседы), помощник в чате (ключ Gemini).

## 2. Что нужно решить владельцу

1. **Какой домен у нового сайта.** В документах проекта записан `an30.ru`, а
   старый магазин в настройке 1С открыт по адресу `an-30.ru`. Нужно назвать
   точное имя.
2. **Этот сервер сразу рабочий или пробный.** База данных при первом запуске
   навсегда помечается как рабочая (`production`) или пробная (`staging`).
   Пробную базу нельзя потом превратить в рабочую, её придётся создавать
   заново. Ниже описана установка рабочего сайта.
3. **Когда открывать приём заказов.** Пока юридические тексты не утверждены,
   на сайте закрыты оформление заказа, регистрация покупателей и формы
   обращений. Каталог, поиск и рабочее место сотрудников работают.
4. **Где хранить вторую копию резервных архивов.** Сейчас копии лежат только
   на самом сервере. Если сервер будет потерян, они пропадут вместе с ним.

## 3. Подготовка чистого сервера

Команды выполняются на сервере под пользователем с `sudo`.

Во всех командах этого документа `your-domain.example`, `user` и
`203.0.113.10` — примеры. Замените их на свой домен, имя пользователя на
сервере и адрес сервера.

```bash
sudo apt-get update && sudo apt-get -y upgrade
sudo apt-get install -y ca-certificates curl gnupg zstd openssl ufw unattended-upgrades

# Сетевой экран: SSH, HTTP (сертификат и переадресация на HTTPS), HTTPS
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw --force enable
```

Docker из официального репозитория:

```bash
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo docker compose version

# Ограничение размера журналов контейнеров (как на тестовом сервере)
printf '%s\n' '{ "log-driver": "local", "log-opts": { "max-size": "10m", "max-file": "5" } }' \
  | sudo tee /etc/docker/daemon.json > /dev/null
sudo systemctl restart docker
```

Каталоги:

```bash
sudo install -d -m 0755 -o "$USER" -g "$USER" /opt/an30
sudo install -d -m 0700 /etc/an30/secrets
sudo install -d -m 0700 /var/backups/an30
```

При сборке сервер скачивает готовые образы с Docker Hub и пакеты из реестра
npm. Оба должны быть доступны с сервера.

## 4. Копирование проекта

**Важно.** Проект копируется из зафиксированного состояния Git. На момент
написания в рабочей папке проекта много незафиксированных изменений, в том
числе 17 из 42 файлов изменений базы данных. Пока они не зафиксированы,
команда ниже отправит на сервер старую версию без обмена с двумя базами 1С и
без подбора по автомобилю. Сначала разработчик фиксирует изменения.

На компьютере разработчика, в папке проекта:

```bash
git status --short | wc -l      # должно быть 0
git archive --format=tar HEAD | gzip > /tmp/an30-src.tar.gz
scp /tmp/an30-src.tar.gz user@203.0.113.10:/tmp/
```

На сервере:

```bash
mkdir -p /opt/an30/app
tar xzf /tmp/an30-src.tar.gz -C /opt/an30/app
ls /opt/an30/app/packages/database/migrations | wc -l    # должно быть 42
```

## 5. Секреты и ключи

Скрипт создаёт пароли базы данных и служебные ключи и пустые файлы для
ключей подключений. Значения он не печатает. Повторный запуск ничего не
перезаписывает.

```bash
sudo env AN30_SECRETS_DIR=/etc/an30/secrets sh /opt/an30/app/scripts/init-secrets.sh
```

Затем впишите ключи, которые у вас есть. В каждом файле **только само
значение**, одной строкой, без кавычек и без `ИМЯ=`.

```bash
sudo nano /etc/an30/secrets/smtp_password.txt
sudo nano /etc/an30/secrets/fapi_key.txt
sudo nano /etc/an30/secrets/rossko_key1.txt
sudo nano /etc/an30/secrets/rossko_key2.txt
# Выровнять права на файлы после правки
sudo env AN30_SECRETS_DIR=/etc/an30/secrets sh /opt/an30/app/scripts/init-secrets.sh
```

| Файл в `/etc/an30/secrets` | Что в нём | Чем включается в файле настроек |
| --- | --- | --- |
| `smtp_password.txt` | Пароль почтового ящика | `SMTP_ENABLED=true` и остальные `SMTP_*` |
| `fapi_key.txt` | Ключ FAPI | Пустой файл выключает FAPI |
| `rossko_key1.txt`, `rossko_key2.txt` | Ключи Rossko | `ROSSKO_ENABLED=true` |
| `telegram_bot_token.txt` | Токен бота Telegram | `TELEGRAM_ENABLED=true`, `TELEGRAM_CHAT_ID` |
| `vk_access_token.txt` | Токен VK для уведомлений | `VK_ENABLED=true`, `VK_PEER_ID` |
| `gemini_api_key.txt` | Ключ Gemini | `AI_ENABLED=true` |
| `reefapi_key.txt` | Ключ ReefAPI | `REEFAPI_ENABLED=true` |
| `api_ninjas_key.txt` | Ключ API Ninjas | `API_NINJAS_MODE=demo` или `commercial` |
| `postgres_password.txt`, `app_database_password.txt`, `redis_password.txt`, `session_secret.txt`, `data_encryption_key.txt` | Создаются скриптом | Не менять после первого запуска |

Замечания:

- В [PARTS_FINDER.md](PARTS_FINDER.md) сказано, что ключи подбора на сервере
  лежат в секрете `parts_finder_env`. Это устарело: сайт на сервере читает
  ключ FAPI из файла `fapi_key.txt`. Локальный файл разработчика
  `secrets/parts_finder.env` содержит строки вида `ИМЯ=значение`, его нельзя
  копировать в `fapi_key.txt` целиком, нужен только сам ключ.
- Сайт не запустится, если подключение включено (`ROSSKO_ENABLED=true`,
  `AI_ENABLED=true`, `REEFAPI_ENABLED=true`), а файл с его ключом пуст.
- Фоновая служба `worker` не запустится, если при `SMTP_ENABLED=true` не
  заданы `SMTP_HOST` и `SMTP_FROM`, если из пары «`SMTP_USER` и пароль»
  задано только одно, или если включены уведомления Telegram либо VK без
  токена и номера чата.
- Сохраните копию каталога `/etc/an30/secrets` в надёжном месте вне сервера.
  Без `data_encryption_key.txt` резервная копия базы не позволит сотрудникам
  войти с прежними одноразовыми кодами.

### Почта через Yandex Cloud Postbox

Сайт отправляет письма сам: подтверждение почты при регистрации, восстановление
пароля, приглашение сотрудника. Настройки для Postbox уже вписаны в примеры
`deploy/staging.env.example` и `deploy/production.env.example`; остаётся
вставить две части ключа и адрес отправителя.

Что сделать в консоли Yandex Cloud (один раз):

1. Postbox → «Создать адрес»: укажите домен сайта. Postbox покажет запись
   DKIM (тип TXT) — добавьте её в DNS домена и дождитесь статуса «Подтверждён».
   Без подтверждённого домена Postbox письма не принимает.
2. Создайте сервисный аккаунт **в том же каталоге**, что и адрес, и дайте ему
   роль `postbox.sender`.
3. У сервисного аккаунта создайте **API-ключ** с областью действия
   `yc.postbox.send`. Консоль один раз покажет идентификатор ключа и его
   секретную часть — сохраните обе.

Что вписать на сервере:

| Куда | Что |
| --- | --- |
| `SMTP_USER` в файле настроек | идентификатор API-ключа |
| `/etc/an30/secrets/smtp_password.txt` | секретная часть API-ключа, одной строкой |
| `SMTP_FROM` | адрес на подтверждённом домене, например `shop@<домен>` |
| `SMTP_FROM_NAME` | имя отправителя, которое видит покупатель (по умолчанию «АН-30») |
| `SMTP_ENABLED` | `true` |

`SMTP_HOST=postbox.cloud.yandex.net`, `SMTP_PORT=587`, `SMTP_SECURE=false` уже
стоят. После правки: `dc up -d --force-recreate worker api`.

Проверка: на сайте «Войти» → «Забыли пароль?» → своя почта. Письмо должно
прийти за минуту. Если не пришло — `dc logs worker | tail -n 50`: причина
отказа почтового сервера записана там (без пароля и без текста письма).

Соединение с почтовым сервером всегда зашифровано; если сервер не отвечает,
служба отступает через 10 секунд и повторяет попытку позже — очередь писем не
останавливается.

## 6. Файл настроек

```bash
sudo install -m 0644 /opt/an30/app/deploy/production.env.example /etc/an30/production.env
sudo nano /etc/an30/production.env
```

Что заполнить (пояснения есть в самом файле):

| Настройка | Значение |
| --- | --- |
| `DEPLOYMENT_ENVIRONMENT` | `production`. Менять после первого запуска нельзя. |
| `APP_BASE_URL` | `https://<домен>` без косой черты в конце. |
| `SITE_ADDRESS` | `<домен>` без `https://`. Тогда сервер сам получает сертификат и переводит обычный HTTP на HTTPS. |
| `WWW_SITE_ADDRESS` | `www.<домен>`, если для `www` есть запись DNS; иначе `http://www.<домен>`. |
| `ACME_EMAIL` | Почта для уведомлений о сертификате. |
| `SMTP_ENABLED`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_FROM`, `SMTP_USER` | Почта. Порт 587 и `SMTP_SECURE=false` либо порт 465 и `SMTP_SECURE=true`. `SMTP_FROM` — просто адрес, без имени. |
| `YANDEX_ID_CLIENT_ID`, `VK_ID_CLIENT_ID` | Идентификаторы приложений. Пусто — кнопок входа нет. |
| `ROSSKO_ENABLED` | `true`, когда вписаны оба ключа Rossko. |
| `ROSSKO_DAILY_LIMIT`, `ROSSKO_CROSS_FILL_DAILY_LIMIT` | Сколько запросов к Rossko сайт делает в сутки всего (по умолчанию 90 000 из разрешённых 100 000) и сколько из них — ночная проверка наших номеров (по умолчанию 4 000; `0` запрещает её). Сама проверка включается в админке. См. [CATALOG_MATCHING.md](CATALOG_MATCHING.md), «Наполнение от поставщика». |
| `SUPPLIER_MARKUP_PERCENT` | Наценка в процентах на цены поставщика, по умолчанию 30. |
| `FAPI_FITMENT_ENABLED`, `FAPI_DAILY_CREDIT_LIMIT` | Подбор машины через FAPI (расходует кредиты) и дневной предел расхода. По умолчанию выключено и 1000. |
| `ONE_C_PRICE_TYPE`, `ONE_C_PRICE_TYPE_SECONDARY` | Обычно пусто. См. [ONE_C_SETUP_UNF.md](ONE_C_SETUP_UNF.md), раздел 5.2. |
| `ENABLE_PUBLIC_CHECKOUT`, `LEGAL_DOCUMENTS_APPROVED` | Оба `false`, пока не утверждены юридические тексты. Сайт не запустится, если включить оформление заказа без утверждённых документов. |

## 7. Запуск

Чтобы не повторять длинную команду, один раз задайте сокращение в текущем
окне терминала:

```bash
dc() { (cd /opt/an30/app && sudo AN30_SECRETS_DIR=/etc/an30/secrets docker compose --env-file /etc/an30/production.env "$@"); }
```

```bash
dc config -q            # проверка настроек; ничего не печатает, если всё верно
dc up -d --build        # сборка и запуск
dc ps -a                # состояние всех служб
```

Первый запуск занимает несколько минут: антивирус загружает базы сигнатур, и
сайт ждёт, пока он будет готов. В списке `dc ps -a` службы `migrate` и
`storage-init` должны быть в состоянии `Exited (0)` — это нормально, они
выполняются один раз и завершаются.

Что входит в установку и проверено по файлам проекта:

| Служба | Назначение |
| --- | --- |
| `caddy` | Единственная точка входа, порты 80 и 443. Запросы `/api/v1/*` и `/ws` передаёт программе сайта (API), всё остальное — витрине. Сертификат HTTPS получает сам. |
| `web` | Витрина и рабочее место сотрудников. |
| `api` | Программа сайта: каталог, заказы, обмен с 1С. Наружу не открыта. |
| `worker` | Фоновые задачи: почта, уведомления. |
| `migrate` | Перед запуском `api` и `worker` приводит базу данных к нужной версии. |
| `postgres`, `redis` | База данных и служебное хранилище. Данные лежат на постоянных томах. |
| `clamav` | Антивирус для загружаемых файлов и фото из 1С. |

Постоянные тома: база данных, Redis, загруженные файлы и фото, сертификаты,
базы антивируса. Временные файлы обмена с 1С лежат на томе загруженных
файлов; сайт ограничивает их объём сам (на каждую базу 1С до 4 ГБ и 100 000
файлов, один файл до 512 МБ).

## 8. База данных и проверка состояния

Изменения базы данных (миграции) применяются сами при каждом `dc up`.
Отдельно запускать их не нужно. Проверка:

```bash
dc logs migrate | tail -n 20
dc run --rm migrate node dist/migrate.js status      # ожидается "pending":0
curl -fsS https://your-domain.example/health/live
curl -fsS https://your-domain.example/health/ready               # база данных, Redis и антивирус доступны
```

## 9. Учётная запись владельца

Первый администратор создаётся один раз командой на сервере. Пароль (от 12
до 128 символов) передаётся через файл, чтобы он не остался в истории
команд. Почту `owner@your-domain.example` замените на почту владельца.

```bash
# Введите пароль, нажмите Enter, затем Ctrl+D
sudo sh -c 'umask 077; cat > /etc/an30/secrets/initial_owner_password.txt'

cd /opt/an30/app
sudo sh -c 'AN30_SECRETS_DIR=/etc/an30/secrets docker compose --env-file /etc/an30/production.env \
  exec -T api node dist/cli/create-owner.js \
  --email owner@your-domain.example \
  --display-name "Владелец АН-30" \
  --password-file /dev/stdin < /etc/an30/secrets/initial_owner_password.txt'

sudo rm /etc/an30/secrets/initial_owner_password.txt
```

Команда отвечает `Owner … created. TOTP setup is mandatory on first login.`
Если сотрудники уже есть, она откажется создавать владельца. Подробнее:
[AUTHENTICATION.md](AUTHENTICATION.md), раздел «Первый владелец».

Затем откройте `https://<домен>/admin`, войдите с этой почтой и паролем.
Сайт попросит настроить одноразовые коды (TOTP) в приложении на телефоне и
покажет резервные коды. Сохраните их отдельно от пароля.

## 10. Обмен с 1С

1. В рабочем месте сайта откройте «Настройки». Для «Основной базы» и
   «Дополнительной базы» задайте имя пользователя, пароль, адрес (IP) 1С и
   включите обмен.
2. Настройте 1С и выполните первый обмен по документу
   [ONE_C_SETUP_UNF.md](ONE_C_SETUP_UNF.md). Перед этим желательно пройти
   пробный обмен на локальном стенде (раздел 10 того же документа).
3. Результат смотрите в рабочем месте сайта, пункт «Импорт 1С».

До первого обмена каталог на сайте пуст: товары приходят только из 1С.

## 11. Резервные копии

Порядок работы, восстановление и проверка архива описаны в
[OPERATIONS.md](OPERATIONS.md), разделы «Резервное копирование» и
«Восстановление». Отличие рабочего сайта: файл настроек называется
`/etc/an30/production.env`, поэтому служба ставится с заменой этого пути.

```bash
sudo sh -c "sed 's#/etc/an30/staging.env#/etc/an30/production.env#' \
  /opt/an30/app/deploy/an30-backup.service > /etc/systemd/system/an30-backup.service"
sudo install -m 0644 /opt/an30/app/deploy/an30-backup.timer /etc/systemd/system/an30-backup.timer
sudo systemctl daemon-reload
sudo systemctl enable --now an30-backup.timer

sudo systemctl start an30-backup.service                 # первая копия сразу
sudo journalctl -u an30-backup.service -n 20 --no-pager  # журнал
sudo ls -l /var/backups/an30
```

Проверка, что архив восстанавливается (рабочие данные не затрагивает):

```bash
cd /opt/an30/app
ARCHIVE=$(sudo sh -c 'ls -1 /var/backups/an30/an30-db-*.dump.zst.gpg | tail -1')
sudo AN30_ENV_FILE=/etc/an30/production.env AN30_SECRETS_DIR=/etc/an30/secrets \
  bash scripts/restore.sh --verify "$ARCHIVE"
```

Обязательно:

- Первая копия создаёт пароль архивов `/etc/an30/secrets/backup_passphrase.txt`.
  **Сохраните его вне сервера.** Без него архивы не открыть.
- Копия делается каждые 15 минут. Все копии хранятся 48 часов, дальше от
  каждых суток остаётся последняя копия, а через 14 дней удаляется и она.
  Каждый раз сохраняется база данных и **весь** том загруженных файлов,
  включая фото из 1С и временные файлы обмена. При большом объёме фото копии
  быстро займут диск. После первого обмена с фотографиями проверьте размер
  каталога `/var/backups/an30` и при необходимости попросите разработчика
  изменить расписание или срок хранения.
- Настройте отправку архивов в другое место. Пока этого нет, потеря сервера
  означает потерю копий.

## 12. Обновление сайта

Порядок описан в [OPERATIONS.md](OPERATIONS.md), разделы «Обновление» и
«Откат». Для рабочего сайта везде вместо `/etc/an30/staging.env`
используется `/etc/an30/production.env`. Коротко:

```bash
sudo systemctl start an30-backup.service        # копия перед обновлением

# на компьютере разработчика
git archive --format=tar HEAD | gzip > /tmp/an30-src.tar.gz
scp /tmp/an30-src.tar.gz user@203.0.113.10:/tmp/

# на сервере: распаковка в чистую папку и подмена; прежняя версия остаётся в app.old
cd /opt/an30 && rm -rf app.new && mkdir -p app.new \
  && tar xzf /tmp/an30-src.tar.gz -C app.new \
  && rm -rf app.old && mv app app.old && mv app.new app

dc up -d --build
dc ps
curl -fsS https://your-domain.example/health/ready

sudo docker builder prune -f                    # после успешной проверки: кеш сборки
```

Кеш сборки Docker сам не очищается и растёт с каждым обновлением (на стенде
за сутки — 44 ГБ из 80). Команда удаляет только кеш, данные сайта не трогает.

Изменения базы данных применяются только вперёд. Если обновление испортило
данные, возврат делается восстановлением из копии, снятой перед обновлением.

После изменения файла настроек или ключа:

```bash
dc up -d --force-recreate api worker web
```

Смена домена (`APP_BASE_URL`) требует пересборки: `dc up -d --build`.

## 13. Что нужно закрыть до открытия сайта покупателям

По важности:

1. **Зафиксировать изменения проекта в Git** (раздел 4). Без этого на сервер
   попадёт старая версия.
2. **Домен и HTTPS.** Сертификат выпускается только на доменное имя. Пока
   в `SITE_ADDRESS` стоит IP-адрес, сайт работает по HTTP, а
   `COOKIE_SECURE=false`. После привязки домена: `DEPLOYMENT_ENVIRONMENT=production`,
   `APP_BASE_URL=https://домен`, `SITE_ADDRESS=домен`, `COOKIE_SECURE=true`,
   пароль на весь сайт снимается (`SITE_PASSWORD_ENABLED=false`), затем
   `dc up -d --build`. Запрет индексации
   снимается этим же шагом: признак рабочего режима передаётся в сборку
   витрины (проверено 23.11.2026: в рабочем режиме `robots.txt` разрешает
   индексацию, заголовка `X-Robots-Tag: noindex` нет).
3. **Пройти настоящий обмен с УНФ.** До сих пор обмен проверялся только на
   подготовленных файлах. Заодно измерить размер файлов выгрузки: сайт
   принимает файл до 512 МБ, но на файлах в сотни мегабайт работа программы
   сайта в отведённой ей памяти (1,5 ГБ) не проверялась.
4. **Вторая копия резервных архивов** вне сервера (раздел 11). Диск: кеш
   сборки очищается после каждого обновления (раздел 12).
5. **История обменов с 1С в базе данных не очищается.** Каждая полная
   выгрузка сохраняется целиком. При ежедневной полной выгрузке двух баз
   база данных будет заметно расти. Нужно наблюдать за диском; очистку
   должен добавить разработчик.
6. **Юридические тексты** по [PRODUCTION_LEGAL_CHECKLIST.md](PRODUCTION_LEGAL_CHECKLIST.md).
   После утверждения в файле настроек ставятся `LEGAL_DOCUMENTS_APPROVED=true`
   и `ENABLE_PUBLIC_CHECKOUT=true`.
7. **Замена старых паролей и ключей** по [SECRET_ROTATION.md](SECRET_ROTATION.md).
8. В [OPERATIONS.md](OPERATIONS.md) есть ссылка на `docs/ADMIN_ACCESS.md`,
   такого файла в проекте нет. Создание владельца описано в разделе 9 этого
   документа и в [AUTHENTICATION.md](AUTHENTICATION.md).
