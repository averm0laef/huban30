# TecDoc (tecdoc.site): каталог автомобилей и применимость

Состояние на 22.11.2026. Код: `apps/api/src/tecdoc`, сайт: `apps/web/app/(store)/podbor`, `_lib/tecdoc.ts`.
Работа с настоящим ключом **ещё не проверялась**: всё собрано по официальному описанию API v2 и проверено на подставном сервере с теми же форматами ответов. Первый шаг после получения ключа — кнопка «Проверить ключ» в админке.

## Что разрешает договор и как это учтено

Оферта tecdoc.site (п. 2.6–2.7.3): API можно использовать только в режиме «запрос — ответ», чтобы показать данные посетителю своего сайта. Запрещены парсинг и автоматический сбор, массовая выгрузка, локальные копии базы (в том числе частичные), «кэширование сверх технологически необходимого для отображения», передача данных третьим лицам. За нарушение — отключение без возврата денег и неустойка от 15 000 000 ₽ (п. 2.5).

| Требование договора | Как сделано |
| --- | --- |
| Только запрос — ответ для посетителя | Каждый вызов делается от имени посетителя, который что-то открыл. В коде нет способа вызвать TecDoc из фоновой задачи: нет ни синхронизации, ни «прогрева», ни обхода каталога. |
| Не создавать копию базы | В PostgreSQL из TecDoc не пишется ничего. Кроссы и применимость TecDoc **не** сохраняются в нашу базу кроссов: наш товар сопоставляется с ответом TecDoc в момент запроса и только для этого ответа. |
| Кеш только для показа | Redis, срок 24 часа (пустые ответы — 1 час), не больше 20 000 ответов, хранится только то, что показывается на странице. Кеш очищается одной кнопкой. |
| Не отдавать третьим лицам | Страницы с данными TecDoc не отдаются поисковикам: данные подгружаются в браузере после действия посетителя, адреса `/api/` закрыты в robots.txt. |
| Не обходить лимиты | Свой учёт запросов строже лимита тарифа (см. ниже). |

В нашей базе остаются только: счётчик запросов по дням (`app.tecdoc_usage_daily`) и гараж покупателя (`app.customer_vehicles`) — название машины, которую покупатель сам выбрал, и номера этого выбора.

**Что нужно подтвердить у tecdoc.site письменно:** допустимый срок кеша (сейчас 24 часа) и показ применимости в карточке товара. Если разрешат больше — меняется одна настройка `TECDOC_CACHE_TTL_SECONDS` (код не позволит больше 7 дней).

## Как покупатель находит деталь

1. **Выбор машины** (`/podbor`, гараж в кабинете): марка → модель → поколение → двигатель, либо VIN. Японские марки первыми. Машина сохраняется на устройстве, у вошедшего покупателя — в гараже.
2. **Каталог запчастей машины**: разделы TecDoc для выбранной модификации; запрос текстом («колодки») сразу находит раздел в уже загруженном дереве — без нового вызова.
3. **Детали раздела**: сначала **наши товары**, которые подходят машине (точный номер + тот же бренд, оригинальный номер, наши подтверждённые кроссы), с ценой, остатком и кнопкой «В корзину». Остальное — по кнопке «Показать все подходящие детали», под заказ.
4. **Поиск по номеру**: если нашего товара с таким номером нет в наличии, TecDoc называет аналоги, и сайт ищет их в нашем каталоге.
5. **Карточка товара**: блок «Применимость к автомобилям» — **только по кнопке**, открытие страницы ничего не тратит, даже с выбранной машиной. С машиной: «Проверить, подойдёт ли к <машина>» (`/search` + `/applicability` по модели машины — 2 запроса; ответ «подходит / с другим двигателем / подходит к модели / не указана») и «К каким машинам подходит» (`/search` + `/part` — 2; `/search` берётся из кеша, обе кнопки подряд — 3). Без машины: «К каким машинам подходит» и «Выбрать мой автомобиль». Ответ держится в браузере до конца посещения (`sessionStorage`). Посетителю — 30 проверок в сутки; дальше, как и при исчерпанном дне пакета, вместо кнопки «Проверим совместимость по VIN» (заявка специалисту). Для масел, химии, инструмента, товаров без бренда и коротких номеров кнопок нет (`partNumberCatalogueApplies` в `packages/contracts`). Проверка — `scripts/storefront-checks/product-fitment.mjs`.
6. **Поиск по названию** («масляный фильтр», «антифриз») идёт только по нашему каталогу и TecDoc не тратит.

Бренд сравнивается по «личности» (`app.brand_identities`: MANN = MANN-FILTER, Toyota = Lexus). Одинаковый номер другого бренда нашим товаром не считается.

Если TecDoc недоступен, отклонил ключ или исчерпан лимит, сайт сам переходит на собственный справочник машин и свой каталог; покупатель не видит сообщений про ключи и лимиты.

## Расход запросов

Тариф «Основной V2 2026»: 150 000 запросов на 30 дней (3 900 ₽), «Продвинутый» — 500 000 (11 900 ₽). Тестовый ключ: 500 запросов в сутки на 7 дней.

| Действие покупателя | Запросов при первом обращении | Повтор в течение суток |
| --- | --- | --- |
| Открыть список марок | 1 на весь сайт | 0 |
| Модели марки | 2 | 0 |
| Двигатели поколения | 1 | 0 |
| Разделы запчастей машины | 1 | 0 |
| Детали раздела — наши товары | 1 + по 1 на наш бренд с совпадением (не больше 6) | 0 |
| «Показать все подходящие детали» | 1 | 0 |
| Применимость в карточке товара | 0 при открытии; 2 на кнопку, обе кнопки — 3 | 0 |
| Поиск аналогов по номеру | 1 | 0 |
| VIN | 1 | 0 |

Один покупатель, который выбрал редкую машину и посмотрел три раздела, — около 12–20 запросов; популярные машины и товары отвечают из кеша. На 150 000 запросов это примерно 250–400 таких «холодных» подборов в сутки, с кешем — в несколько раз больше посетителей.

**Защита от перерасхода** (`tecdoc-budget.ts`):
- дневной лимит считается сам: остаток пакета (с запасом 3 %) делится на оставшиеся дни периода — 150 000 дают около 4 850 в сутки; тихие дни увеличивают лимит следующих;
- за любой час — не больше пятой части дневного лимита;
- один посетитель — не больше 150 запросов к каталогу в сутки (кеш не считается);
- одинаковые одновременные запросы делают один вызов;
- после отказа ключа сайт не дёргает сервис 10 минут, после пяти сбоев подряд — минуту.

Расход, лимиты, долю ответов из кеша и последнюю ошибку показывает админка: «Настройки» → «Подбор и поставщики» → «Каталог TecDoc».

## Запуск после получения ключа

1. Положить ключ в файл секрета `tecdoc_api_key.txt` (на сервере `/etc/an30/secrets/`, локально — переменная `TECDOC_API_KEY`). Ключ передаётся только в заголовке `X-API-KEY`, в адресах и журналах его нет.
2. В настройках сервера указать пакет и дату покупки: `TECDOC_MONTHLY_LIMIT=150000`, `TECDOC_PERIOD_START=ГГГГ-ММ-ДД`. Для тестового ключа вместо этого `TECDOC_DAILY_LIMIT=450`.
3. Перезапустить `api`.
4. В админке нажать «Проверить ключ» (до 6 запросов): должно показать число марок, моделей, двигателей и разделов. Если где-то ноль — формат ответа отличается от описания, это правится в `tecdoc-normalize.ts`.
5. Пройти на сайте: `/podbor` → выбрать машину → раздел → деталь; открыть карточку товара с выбранной машиной.

Без ключа ничего не ломается: сайт работает на собственном справочнике машин.

## Настройки

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `TECDOC_API_KEY_FILE` / `TECDOC_API_KEY` | — | ключ; без него TecDoc выключен |
| `TECDOC_ENABLED` | true | `false` выключает при заданном ключе |
| `TECDOC_MONTHLY_LIMIT` | 150000 | купленный пакет |
| `TECDOC_PERIOD_START` | — | дата покупки пакета; без неё считается календарный месяц |
| `TECDOC_DAILY_LIMIT`, `TECDOC_HOURLY_LIMIT` | 0 | 0 — считать автоматически |
| `TECDOC_VISITOR_DAILY_LIMIT` | 150 | на одного посетителя в сутки |
| `TECDOC_CACHE_TTL_SECONDS` | 86400 | срок кеша показа |
| `TECDOC_CACHE_MAX_ENTRIES` | 20000 | сколько ответов держит кеш |

## Независимость от TecDoc

TecDoc — источник применимости, но не основа каталога. Товары, цены, остатки, разделы, поиск и собственные кроссы живут у нас и работают без него (см. [OWN_CATALOG.md](OWN_CATALOG.md)). При расторжении договора: убрать ключ, нажать «Очистить кеш» — на сайте останутся собственный справочник машин и свой каталог; в базе данных TecDoc нет, удалять нечего.
