# UMAPI: проверка совместимости, аналоги, идентификация деталей

Концепция владельца «Интеллектуальный каталог автозапчастей» (версия 1.0), сверенная с тем, что уже есть в проекте, и с настоящей документацией API UMAPI (OpenAPI 2.1.1, https://api.umapi.ru/documentation, прочитана 23.11.2026). Справочник машин из купленного файла уже работает — см. [UMAPI.md](UMAPI.md).

**Главный принцип концепции остаётся:** основа — собственная база магазина. UMAPI нужен для того, что самим сделать дорого:
- идентификация детали;
- применимость к машине;
- аналоги — в пределах лицензии.

Поиск, каталог и выбор машины от UMAPI не зависят.

## 1. Что в концепции поправлено под наш проект

ИИ — только для остатка, который правила не разобрали, и только как предложение в «Качестве каталога». В тестах платные провайдеры не вызываются. |

| Проверка совместимости | Уже есть кнопочная проверка для TecDoc: блок «Применимость» в карточке, бюджет запросов по дням, кеш, лимит на посетителя | Меняется источник: TecDoc → UMAPI. Кнопки, бюджет, тексты и правило «только по кнопке» остаются. |

## 2. API UMAPI — как он устроен на самом деле

- **Адрес:** `https://api.umapi.ru/v2/autocatalog/{язык}-{регион}/…`. Язык `ru`, регион по умолчанию `WWW`. Регион `RUS` или `RU` — проверить, меняет ли он ответы.
- **Ключ:** HTTP-заголовок **`X-App-Key`**.
- **Ошибки в документации:**
  - `400` — неверный запрос;
  - `401` — ключ не принят;
  - `402` — «Payment Required»: метод не оплачен или исчерпан пакет;
  - `500` — ошибка сервиса.

  Ответ `429` и лимиты скорости не описаны — спросить у UMAPI.
- **Тип машины:** параметр `type` — `PC` (легковые), `CV` (коммерческие), `Motorcycle`, `Engine`, `Axle`.

Нужные методы:

| Метод | Что даёт | Для чего у нас |
|---|---|---|
| `Manufacturers?type=PC` | марки (`MFA_ID`) | только сверка номеров со справочником |
| `ModelSeries?MFA_ID=…` | модели (`MS_ID`) | только сверка |
| `Passangers?MS_ID=…` (так в API, с ошибкой в слове) | модификации: `PC_ID`, мощность, объём, кузов, топливо; с `Engines=true` — коды двигателей `ENG_CODE` | сверка и **коды двигателей**, которых нет в файле (там они только у 22% модификаций) |
| `BrandRefinement/{номер}` | чьи детали с этим номером: `BRAND`, `BRA_ID`, `TYPE`, `TITLE` | выбор бренда для номера; вопрос «чья деталь» при поиске |
| `Analogs/{номер}/{бренд}` | аналоги: `ART_ID`, `ARTICLE_NR`, `BRAND`, `DES`, `REPLACEMENT` | кнопка «Аналоги»: сопоставление с нашими товарами в памяти |
| `Article/{ART_ID}` | карточка детали: характеристики (`CRITERIAS`), фото (`MEDIAS`), OE-номера, EAN, состав комплекта | характеристики и фото — только если лицензия разрешает показ |
| `ArticleLinks/{ART_ID}` | применимость: списки `PC[]` (`MFA_ID`, `MS_ID`, `PC_ID`), `CV[]`, `Engine[]` и др. | **проверка совместимости** |
| `Categories`, `Products`, `Articles` (по `ID` модификации) | дерево деталей машины и детали в нём | «Детали для моей машины» по запросу — позже |
| `/v2/cross/...` | отдельный сервис кроссов и EAN | уточнить у UMAPI, чем отличается и как тарифицируется |
| `/v1/to/...` | «Каталог ТО» (марки, модели, модификации) | возможно, готовые наборы ТО — уточнить |

**Как получить `ART_ID` (проверено ключом владельца 23.11.2026).** В автокаталоге метода «номер и бренд → `ART_ID`» нет, а `Analogs/{номер}/{бренд}` саму деталь **не** возвращает, только аналоги. `ART_ID` даёт сервис кроссов: `GET /v2/cross/parts/Analogs/getCrossInfo?article=…&brand=…` → `{article, brand, title, catalogId, td: {ART_ID, ARTICLE_NR, SUP_ID, BRAND, COMPLETE_DES, MEDIAS[]}}`. В том же ответе есть фото, отдельный запрос `Article/{ART_ID}` не нужен.

**Что ещё показал настоящий ключ:**
- **Номера машин совпадают с файлом:** марки 735 из 735, у Sprinter 3,5-t Фургон (`MS_ID` 5590) 23 из 23 `PC_ID`. Таблица соответствия не нужна.
- **`BrandRefinement` отдаёт и чужие кроссы.** Строки с `TYPE: "IAMNumber"` — это номера других брендов, у которых есть такой кросс. Производитель детали — только строки `TYPE: "ArticleNumber"`.
- **Номер передаётся без пробелов и знаков.** `BrandRefinement/W9142` находит MANN-FILTER W 914/2, а `BrandRefinement/W914%2F2` возвращает пустой список. Модуль всегда спрашивает «голый» номер (`normalizeArticleNumber`).
- **Фото:** `https://image.umapi.ru/IMAGE/{SUP_ID}/{FILE_NAME}` (настройка `UMAPI_MEDIA_BASE_URL`).
- **Контрольный товар.** AFW1272 по `BrandRefinement` — бренд MILES. K1288 — FILTRON (`ART_ID` 7705805). CU3569 — MANN-FILTER.

## 3. Первая проверка с ключом

1. Положите ключ одной строкой в `secrets/umapi_api_key.txt`. Папка `secrets/` не попадает в Git. Ключ никуда не присылайте.
2. Соберите пакет базы данных, если он ещё не собран: `corepack pnpm --filter @an30/database build`.
3. Запустите:
   ```bash
   node scripts/umapi-checks/probe.mjs
   ```
   Скрипт сделает около 10 запросов и ничего не сохранит.

Что он выясняет:
- **Работает ли ключ** и сколько длится запрос. При ответе `402` понятно, какой метод не входит в тариф.
- **Совпадают ли номера машин API с купленным файлом:** `MFA_ID`, `MS_ID`, `PC_ID` ↔ `PCS_PC_ID`. От этого зависит, подходит ли наш справочник к API напрямую. Если не совпадут — нужна таблица соответствия, и это отдельная задача.
- **Контрольный сценарий:**
  - для номеров AFW1272, K1288 и CU3569 — какие бренды ими называются;
  - достаётся ли `ART_ID`;
  - есть ли в применимости Mercedes-Benz Sprinter 3,5-t Фургон (B906), `MS_ID` 5590, 23 модификации.

## 3а. Как устроено в коде

- **API** — `apps/api/src/umapi/`:
  - `umapi.gateway.ts` — запросы с ключом, таймаут, пауза при отказе ключа или тарифа;
  - `umapi-budget.service.ts` и `umapi-cache.service.ts` — лимиты и кеш Redis (`an30:umapi:*`, 24 часа);
  - `umapi-identify.ts` — кандидаты: свой бренд и артикул, номера из скобок названия;
  - `umapi-fitment.ts` — вердикт по выбранной модификации и список машин;
  - `umapi.service.ts` — сценарии кнопок.
- **Маршруты**:
  - `GET /api/v1/umapi/status`;
  - `GET /api/v1/umapi/product/:id/fitment?mode=check|list&model&mod`;
  - `GET /api/v1/umapi/product/:id/analogs`;
  - `GET /api/v1/umapi/product/:id/photos`;
  - для сотрудников — `GET /staff/umapi/status` и `POST /staff/umapi/cache/clear` (право `catalog:write`).
- **Сайт** — карточка товара: `product-catalogue-check.tsx`, кнопки в `product-gallery.tsx` и `product-analogs.tsx`, загрузка — `_components/wheel-loader.tsx`. Для масел, жидкостей и прочего, чего нет в каталоге применимости (`umapiCatalogueApplies` в `packages/contracts`), остаётся «Проверить по VIN».
- **Настройки** — `UMAPI_*` в `compose.yaml`, ключ — секрет `umapi_api_key` (`scripts/init-secrets.sh`). На стенде `scripts/dev/run-api-preview.sh` берёт ключ из `secrets/umapi_api_key.txt`.
- **Без ключа и без платных запросов**: `node scripts/umapi-checks/stub-server.mjs` — подставной UMAPI на :4100 с выдуманными данными.

## 4. Контрольный сценарий на наших данных

**Товар** — настоящая строка выгрузки 1С:

```text
Фильтр салона MB SPRINTER/VW CRAFTER 06- AFW1272 (FILTRON K1288, MANN CU3569) AFW1272
```

Код 1С `00-00009652`, артикул `AFW1272`, цена 400 ₽, остаток 1, бренд в 1С не указан.

**Машина.** В справочнике у Sprinter B906 двенадцать «моделей»: 3-t, 3,5-t, 4,6-t и 5-t, каждая в трёх кузовах (автобус, фургон, борт). Например, `MS_ID` 5590 — «SPRINTER 3,5-t Фургон (B906)», 23 модификации, от 309 CDI до 519 CDI. Концепция права: одного «W906» мало, нужна модификация. В нашем меню это шаги «Поколение» и «Двигатель».

**Как идентифицировать товар.** Сервер берёт товар по его номеру в базе. Номера с сайта для проверки не принимаются — так уже устроена проверка TecDoc.

1. **Свой бренд и артикул товара.** Если бренд из 1С или из названия известен, это основной кандидат.
2. **Номера из названия** (их достаёт словарь деталей): `FILTRON K1288`, `MANN CU3569`. Это не номер самого товара, а его аналоги. Бренд AFW (если это бренд) неизвестен.
3. **Голый код без бренда** (`AFW1272`) проверяется через `BrandRefinement`. Однозначным считается только ответ с одним брендом. Несколько брендов → «не удалось однозначно определить товар».
4. **Совместимость.** `ArticleLinks` для каждого кандидата, затем поиск `PC_ID` выбранной модификации в `PC[]`:
   - есть → «подходит»;
   - есть только тот же `MS_ID` → «подходит к модели, сверьте двигатель»;
   - нет → «в каталоге не указан».
5. **Если товар узнан только по номерам-аналогам**, ответ помечается «по номерам-аналогам из названия (FILTRON K1288)»:
   - оба кандидата согласны → показываем результат;
   - кандидаты спорят → «Не уверены — проверим по VIN».

Ошибка или недоступность UMAPI — это никогда не «не подходит».

## 6. Хранение и лицензия

По подтверждению владельца от 24.11.2026 разрешены показ фотографий UMAPI по запросу посетителя, кеширование до 24 часов и отдельное внутреннее хранение фото для подготовки загрузки в 1С. Для показа используется `UMAPI_MEDIA_BASE_URL=https://image.umapi.ru/IMAGE`.

- Нажатие «Показать фото из каталога» или «Обновить фото из каталога» отправляет свежие запросы в UMAPI с соблюдением лимитов. При сбое отображается ошибка и возможность обратиться в магазин.
- Кеш ответов Redis хранится до 24 часов. Он используется для применимости и аналогов. Запрос фото всегда проходит в UMAPI, включая повторное нажатие.
- Связи при совпадении артикула и бренда сохраняются отдельно в `app.umapi_product_photos`. В «Каталог → Фото товаров → UMAPI для 1С» сотрудник с правом `catalog:write` видит источник, товар и код 1С, сохраняет проверенный JPEG и скачивает его. Запись и файл служебные. Фото, найденное по номеру аналога в названии, показывается только как справочное.
- Имя скачанного JPEG содержит `-an30-umapi-` и идентификатор файла. Сайт пропускает этот файл при обратной выгрузке 1С по имени и отпечатку. Загружайте его в 1С для внутреннего использования. Публикация снимков из 1С и прав на них ведётся в действующем разделе фото.
- Списки аналогов и применимость остаются в Redis. Запросы посетителей и личные данные в архив фото не записываются.

Открыты вопросы о праве на показ характеристик (`CRITERIAS`), хранении кодов двигателей, тарификации методов кроссов и выборе региона.

## 7. Бюджет запросов

Устроено так же, как для TecDoc (`tecdoc-budget.ts`):
- сутки делятся на доли по задачам;
- посетителю — до 40 нажатий кнопок в сутки с одного IP;
- при исчерпании вместо кнопки — «Проверим по VIN».

**Стоимость одной кнопки:**
- «Подходит ли к моему авто»: `BrandRefinement` (1) + `getCrossInfo` (1) + `ArticleLinks` (1) — **3 запроса** на номер; для товара без бренда, узнанного по номерам-аналогам из названия, — по 3 на каждый номер. Служебные привязки фото для этого расчёта не используются.
- «К каким машинам подходит» — тот же `ArticleLinks`. Повторное нажатие в течение 24 часов — 0 запросов (кеш).
- «Аналоги» — после опознания детали ещё `Analogs` (1). Сопоставление с нашим складом в памяти.
- «Фото из каталога» — свежий `BrandRefinement` и `getCrossInfo` на подходящий номер. Порог 120 обращений к поставщику на посетителя сохраняется.

Лимиты (решение владельца 24.11.2026, пока сайт закрыт паролем): только общий потолок магазина `UMAPI_DAILY_LIMIT` — 10 000 запросов в сутки, как в тарифе. Часовой доли нет (`UMAPI_HOURLY_LIMIT=0`), лимита посетителя нет (`UMAPI_VISITOR_DAILY_LIMIT=0`), кнопки с одного адреса не считаются. Перед открытием сайта лимиты посетителя стоит вернуть: задать `UMAPI_VISITOR_DAILY_LIMIT` и `UMAPI_HOURLY_LIMIT`. Счёт по дням — таблица `app.umapi_usage_daily` (миграция 0058); там только числа, никаких данных UMAPI.

**Открытие карточки, поиск и выбор машины — 0 запросов.**

## 8. Порядок работ

| Шаг | Что | Готовность |
|---|---|---|
| 0 | Справочник машин из файла, выбор машины без запросов | сделано (`UMAPI.md`) |
| 1 | Ключ + `scripts/umapi-checks/probe.mjs`: ключ, номера машин, контрольный товар | сделано 23.11.2026 |
| 2 | Модуль `apps/api/src/umapi/`: шлюз (`X-App-Key`, таймауты, пауза при 401/402/403/429), разбор ответов, бюджет, кеш Redis. Тесты только на подставных ответах | сделано |
| 3 | Идентификация товара: свой бренд и артикул → номера из названия → `BrandRefinement`; статусы `ambiguous` и `unknown_part` | сделано |
| 4 | Проверка совместимости в карточке: кнопки «Проверить совместимость» и «К каким машинам подходит»; модификация — из нашего справочника (`umapi_id`) | сделано |
| 5 | «Аналоги» по кнопке: `Analogs` → в памяти → только наши товары с тем же брендом и номером (правило `same-part-number.ts`) | сделано |
| 5а | Фото по кнопке со свежим ответом UMAPI. Служебный архив снимков для 1С | разрешено владельцем и доступно при заполненном `UMAPI_MEDIA_BASE_URL` |
| 6 | Коды двигателей из `Passangers?Engines=true` для справочника. Это хранение данных API — только с разрешения UMAPI | по ответу UMAPI |
| 7 | Отключение TecDoc: убрать ключ, очистить кеш; `docs/TECDOC.md` → «отключён» | после шага 4 |

Чего из концепции **не делаем отдельно**, потому что уже есть:
- поиск;
- разделы каталога;
- словари брендов;
- разбор названий 1С;
- экран проверки качества каталога;
- выбор машины.

Массовая идентификация всех 42 723 товаров через UMAPI — только после ответа на вопрос 1 о хранении `ART_ID`. Иначе это тысячи запросов на данные, которые нельзя сохранить.
